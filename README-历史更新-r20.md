## v0.01 r20 完整发行

- Windows：当前用户安装版（控制面板可卸载）、绿色 ZIP 和单独 EXE；卸载保留个人 data 配置。
- Linux x86-64：DEB、RPM、通用 tar.gz，原生 GTK3 / WebKitGTK 4.1 桌面；使用 Ubuntu 22.04 / glibc 2.35 构建基线。
- 密钥管理器统一保存私钥口令，所有引用该密钥的连接自动使用；本地历史列表收集所有 VPS 的命令。
- 上行、下行与延迟曲线独立设置并保存；文件用户／用户组显示名称，大小和修改时间可双向排序。
- 官网下载文件、构建号和 SHA-256 统一更新；特色功能通过实际操作录制为 15 FPS 动态 WebP。
- Windows 安装／卸载仍需真实 Windows 核验；Linux 的容器原生启动证据不能代替实体桌面验证。详见 build/RELEASE-v0.01-r20.md。

- 便携数据统一到程序旁 `data/`；旧版散落配置验证后迁入。SSH、密钥库、自定义字体/背景和全部偏好随目录保留，升级不覆盖。AES-256-GCM 配置自动解锁，明文仅在内存；密钥随目录存在，因此不能防御拥有该目录读取/写入权限的程序。
- 启动更新检查最多 3 秒，固定检测官网 `up.exe.json` / `up.deb.json` 中的 SHA-256 描述；描述采用 schema 2，`build` 必须高于当前程序和安装收据的最大构建号，数字显示版本不得倒退；每次发布均须递增 `internal/app/updates.go` 的 `ApplicationBuild`。旧 schema、旧构建和缺少构建号的描述不提供安装。确认后下载固定 `up.exe` / `up.deb`，校验并重启安装。Linux 包安装需要系统授权。详情见 `build/ONLINE-UPDATE-DESIGN.md`。
- 设置底部提供官网入口；独立官网为可直接上传 aaPanel 的静态站点，适用于 Nginx + PHP 8.3，无构建或数据库要求。

## 已有功能

服务器分组、无限层级分组、可搜索 emoji/国旗、拼音和自然数字排序、历史连接与连接回收区；多 SSH 会话；密码、私钥/加密私钥、SSH Agent；密钥库导入/生成/公钥复制；独立 SOCKS5/HTTP CONNECT 代理；系统/网络/磁盘监控；本机及远端 MTR（含 ASN `-z`）与按需确认安装；SFTP 拖拽文件/目录上传、4 文件并发队列、分块并行、传输进度、重试；彩色胶囊快捷命令；实际 Shell 提交的命令历史及复制/执行；3.5 秒启动动画、首次引导、可搜索使用手册。

终端复制使用 Ctrl+Shift+C，粘贴使用 Ctrl+Shift+V / 右键；Ctrl+C 保留中断语义。粘贴后的远程 Readline 高亮属于 Shell 的括号粘贴区域，输入或执行后由远程 Shell 更新。

## 运行和备份

Windows：运行 `DengShell.exe`。需要 Microsoft Edge WebView2，首次缺少时会引导。未签名 EXE 的下载安全提示由 Windows 管理，程序不能承诺消除；本项目不关闭系统安全策略。

Linux 版本：Debian/Ubuntu 安装 `up.deb`，从应用菜单打开；其他发行版按 `build/linux/README.txt` 选择对应包。r20 使用 Ubuntu 22.04 / glibc 2.35 构建基线，依赖 GTK3、WebKitGTK 4.1；不支持 musl/Alpine、ARM 或缺少对应运行库的旧发行版。本轮提供与 Windows 相同 r20 源码的 Linux 原生二进制。

便携目录只有主程序和 `data/`。配置位于 `data/dengshell.config.enc`，自动解锁密钥 `data/dengshell.config.key`；背景/字体、密钥库分别在 `data/assets/`、`data/keys/`。说明和许可证位于 `data/docs/`、`data/licenses/`。请退出后备份整个 `data/`，不要只备份 `.enc`。导入资源已复制，自定义源文件移动不会丢失；手动填写的外部私钥路径需自行保留。

deb 安装文件位于 `/opt/dengshell`，用户数据在 `${XDG_CONFIG_HOME:-$HOME/.config}/dengshell`。便携升级到 deb 时，更新器显式传入原配置目录，继续读取原数据。设置 → 连接配置文档显示实际目录。`--config /绝对路径` 始终精确指定数据目录，不追加 `data`。

## 源码与构建

需要 Go 1.26+；源码已带前端与字体资源，无需运行 Node 构建。更新 xterm 依赖时运行 `npm ci && npm run vendor`。

```sh
./build.sh               # Ubuntu GTK3 + WebKitGTK 4.1 桌面
./build.sh --windows     # Windows x64，含任务栏图标/高 DPI manifest
./build.sh --browser     # 本机浏览器模式
./dengshell-server --browser --config /可写目录 --addr 127.0.0.1:17880
```

浏览器模式请打开本次启动输出的完整地址（包含 `#token=...`）。启动凭据会立即从地址栏移除，并仅保存在该浏览器标签的会话存储中；裸地址、其他网站及不透明来源不能读取启动令牌。请勿把完整启动地址分享给其他人。可选的本机 SSH 集成测试除 `CLOUDSHELL_TEST_KEY` 外，还要求用专用测试主机公钥计算并设置 `CLOUDSHELL_TEST_HOST_FINGERPRINT=SHA256:...`，测试不会自动信任网络返回的主机指纹。

Windows 本地构建使用 `build-windows.ps1`。运行库初始化成功后保存标记，后续跳过应用的重复检测；底层动态加载器/WebView2 自身仍需能加载。

```sh
go test ./...
go test -race ./internal/app
npm run check
node scripts/test-text-model.mjs
node scripts/test-latency-chart.mjs
node scripts/test-upload-queue.mjs
```

发布源码不含个人服务器配置、私钥、导入的用户资源或构建缓存。Ubuntu 已做原生窗口/托盘验证；Windows 在 Ubuntu 交叉编译，真实 Windows 桌面效果仍需在目标电脑验证。
