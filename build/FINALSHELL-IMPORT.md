# 从 FinalShell 导入 SSH 配置和私钥

R29 支持从 `key` 子文件夹自动导入、关联私钥。密码解析和连接分组延续原有导入方式。

## 操作步骤

1. 在 FinalShell 连接列表中选择连接，右键 → 导出 → 当前选中或全部；如导出压缩包，请先解压。
2. 将导出文件夹命名为 `finalshell_oot_pot`，放在 DengShell 主程序旁。
3. 将私钥放入其中的 `key` 子文件夹。普通 PEM/OpenSSH 私钥以连接 JSON 中的 `secret_key_id` 命名，可保留 `.pem` 等单个扩展名。不要使用公钥 `.pub` 文件代替私钥。
4. 打开 **设置 → 从 FinalShell 导入**，程序自动扫描，保存连接、密码及私钥，并按密钥 ID 自动关联。

```text
DengShell/
├── DengShell.exe
└── finalshell_oot_pot/
    ├── 日常使用/
    │   └── 示例_connect_config.json
    └── key/
        └── 示例连接的secret_key_id.pem
```

导入窗口会显示实际扫描目录。查找位置以主程序目录为准，不取决于启动时的工作目录；`finalshell_oot_pot` 位于其他文件夹时，需要把它放到窗口显示的位置。

## 密钥匹配和重复导入

- 一个密钥 ID 可被多个连接引用，程序自动批量关联；同一份私钥只保存一份。
- 除普通 PEM/OpenSSH 私钥，也支持包含内嵌私钥内容的 JSON：`id` 或 `secret_key_id` 用于匹配，私钥内容字段支持 `private_key`、`privateKey`、`key_data` 或 `key`，`name` 为可选名称。不同 FinalShell 版本的专有导出格式不保证均支持；不支持的文件会列出原因。
- 不按排列顺序、连接数量或相近名称猜测私钥。同一 ID 对应不同私钥时，不自动关联该 ID。
- 私钥复制到 DengShell 密钥管理器目录，连接不再依赖原始导出路径。导入成功后移走原始导出文件不会影响已关联连接。
- 之前已经导入过连接也可重新扫描：只补齐尚未配置的密钥关联，保留手动选择的密钥、连接名称、密码及分组，不恢复回收站记录，不重复创建连接。
- 仍没有匹配私钥时，保留连接，**点击连接时才提示重新配置密钥**。已导入的私钥文件后来丢失，也会提示重新配置。

## 密码与私钥口令

密码登录的密码在本机解析并存入 DengShell 的加密配置，不需要 Python 插件。没有保存密码或密码解析失败时，连接基本信息仍可导入，并提示补充密码。

加密私钥可先导入，不会要求逐个连接填写口令。请在 **密钥管理器 → 编辑该密钥** 中保存一次正确口令，所有引用它的连接都可使用；未保存时，连接会请求私钥口令。包含口令的密钥 JSON 只有在口令实际解锁成功后才保存口令。连接 JSON 中的 `password` 可能是旧账号密码，不会被当作私钥口令。

## 读取范围

导入不修改原文件，不执行脚本，不自动连接服务器。连接子目录保留为分组；仅凭 JSON 的 `parent_id` 无法还原未导出的分组名称。代理引用、非 UTF-8 终端、已删除或不支持的连接类型会报告原因，端口转发规则不导入。

每批最多 2,000 个连接和 256 个密钥文件，连接文件最多 1 MiB，单个私钥最多 2 MiB，整批合计最多 32 MiB。跳过符号链接及特殊文件，读取范围限定在导出目录内；配置保存失败或整批扫描中断时回滚新增连接和私钥副本。

原有用户配置、密钥、字体、背景和历史保留。Linux 安装版会显示实际程序目录，放入导出文件夹时可能需要该目录的写权限。
