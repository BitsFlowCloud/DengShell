# 从 FinalShell 导入 SSH 配置

此功能从 r25 开始实现，在 R28 完整发行包中提供。

## 操作方式

1. 打开 FinalShell，在连接列表中选中一个 SSH 配置。
2. 右键 → **导出** → **当前选中** 或 **全部**。
3. 新建一个名称为 **`finalshell_oot_pot`** 的文件夹，将导出的 `*_connect_config.json` 放进去；如果导出结果是压缩包，请先解压。
4. 把整个文件夹放在 DengShell 主程序旁。Windows 目录示例：

   ```text
   DengShell/
   ├── DengShell.exe
   ├── data/
   └── finalshell_oot_pot/
       ├── 密码连接_connect_config.json
       └── 密钥连接_connect_config.json
   ```

5. 打开 DengShell，点击 **设置 → 从 FinalShell 导入**，程序自动扫描并导入。窗口显示本次实际扫描的绝对目录、每个文件的结果，以及“重新扫描并导入”按钮。
6. 导入的连接位于 **FinalShell 导入** 分组。文件夹内的实际子目录会保留为子分组；仅凭 JSON 内的 `parent_id` 不能还原未导出的分组名称。
7. 对密钥连接点击 **补充私钥**，从密钥管理器选择已导入的密钥，或选择对应的私钥文件，然后保存连接。

文件夹名称按用户提供的约定保留为 `finalshell_oot_pot`，不是 `finalshell_output`。程序根据主程序所在位置查找，不根据启动时的工作目录查找，也不扫描其他软件的安装目录。

## 密码和密钥

密码登录的兼容解析已内置到 Go 后端，不依赖 Python、不下载或运行第三方插件。密码字段在本机解析，写入 DengShell 原有的 AES-GCM 加密配置；API 返回和导入结果只显示保存状态。解析失败或没有保存密码时，连接基本信息仍可导入，并明确提示补充密码。

密钥登录 JSON 的 `secret_key_id` 是 FinalShell 自己的密钥引用，并非私钥内容。密钥模式中的 `password` 字段可能是以前保存的账号密码，导入器不会把它当作私钥口令。连接保持密钥模式，在补充私钥前，点击连接会打开编辑器，不会询问无关口令或发起 SSH 请求。

密码格式依据用户提供的 [FinalShell 解码参考项目](https://github.com/sncce/finalshell-decoder-use-python) 核对，参考提交为 `642cd1ee43655e6aac79ebe96d9356bb55a87a17`。采用标准库独立实现旧格式的 Java 随机数派生、DES 解码及严格填充／UTF-8 检查；第三方脚本未打包进软件。DES 仅用于读取旧格式，DengShell 不用它保存新配置。

## 导入规则

- 导入名称、主机、端口、用户名及认证方式；密码模式同时尝试读取保存的密码。
- 仅接收 SSH 类型 `100` 和密码／密钥认证类型 `1 / 2`。支持 UTF-8 JSON 和 Windows UTF-8 BOM。
- 重复扫描按导出连接标识或相同连接信息识别已有记录，保留 DengShell 中的改名、密码和密钥设置。回收站中的相同记录也不会被重复创建。
- 不删除、移动或修改原始导出文件，不自动连接服务器，不执行导出目录中的脚本或连接记录里的命令。
- 引用独立代理、非 UTF-8 终端、未知认证类型或已删除的记录会明确报告未导入；不猜测代理信息或悄悄改成直连。端口转发规则不导入，并在对应记录中提示。
- 单个 JSON 最大 1 MiB，每批最多 2,000 个连接、32 MiB 数据。跳过符号链接及非普通文件，限制目录层级和扫描条目数。文件错误逐项报告；目录读取错误、整批超限、取消或配置保存失败时，不留下本批部分写入的配置。
- 原有服务器、密钥、主机指纹、字体、背景、颜色、历史和布局保留。
