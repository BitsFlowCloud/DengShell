# 配置目录、升级与备份

便携应用目录只有主程序和 `data/`。首次启动在 `data/` 自动生成配置；deb 安装版使用 `${XDG_CONFIG_HOME:-$HOME/.config}/dengshell`。设置 → 连接配置文档可复制实际位置。显式 `--config` 使用指定目录本身。

| 配置目录内的路径 | 用途 |
|---|---|
| dengshell.config.enc | AES-256-GCM 加密：服务器、保存的密码/口令、分组、连接/命令历史、快捷命令、代理、资源引用、主题、字号、窗口/缩放/布局、托盘等偏好 |
| dengshell.config.key | 32 字节自动解锁密钥，与配置一起备份 |
| dengshell.config.enc.bak | 上次成功写入前的加密配置；不等于整个目录备份 |
| assets/ | 导入字体和背景的程序副本 |
| keys/ | 密钥库私钥副本 |
| opened/ | 系统关联打开的本地文件副本；修改后手动上传 |
| updates/、temporary/ | 下载/更新/打包临时数据 |
| runtime-success-v1-* | 当前平台运行环境曾成功初始化的标记 |
| docs/、licenses/、support/ | 便携包说明、第三方许可证与 Linux 启动器 |

升级时退出应用，只替换主程序，保留完整配置目录。迁移电脑时复制主程序与整个 `data/`；不能只复制 `.enc` 而遗漏 `.key`、`assets/` 或 `keys/`。导入字体/背景之后，原始文件可移动；外部私钥路径不是密钥库副本，必须另行迁移。

旧版散落在程序旁的 `.enc`、`.key`、资源与密钥库会先复制到临时目录并解密验证，然后整体迁入 `data/`；失败保留旧数据。若两个目录都已经包含用户数据，不自动合并覆盖。旧 JSON 转为加密配置前保留加密迁移备份。不会扫描不相关的旧用户目录。

加密配置只在内存解密；自动解锁密钥必须可被程序读取，因此不是对同权限恶意程序的安全边界，不能防止整个目录被删除。应保留离线备份。

可读结构示例见 `config.example.json`，仅说明字段，不能把它当成发布的真实配置。新版配置仍能读取旧版偏好，缺失字段使用默认值。源代码和官网发布包不能包含用户的真实配置或凭据。
