# R40 Windows 断开诊断版

内部构建号：20260915042。保持 R40 名称，后续更高构建号可通过原有自动更新机制升级。

退出正在运行的 DengShell，用本次 `DengShell.exe` 替换原程序，保留原来的 `data` 目录，然后在经常断开的网络下正常使用。诊断会自动启动，无需运行额外脚本。

发生断开后，终端与顶部状态栏会显示 `DS-xxx` 诊断码。终端同时显示连接编号及诊断日志的完整路径。请反馈断开时间、诊断码和连接编号，并提供相应日志文件。

日志默认位于 EXE 旁的 `data/logs/ssh-disconnect.jsonl`。如果通过 `--config` 指定了配置目录，日志位于该目录的 `logs` 中。最多保留当前文件及 `.1`、`.2` 两份旧日志，总计约 3 MiB；需要反馈时可一起提供这三个文件，不需要发送整个 `data` 目录。

| 诊断码 | 触发条件 |
| --- | --- |
| DS-100 / DS-101 | 主动断开、重连、关闭连接 / 退出应用，属于正常关闭 |
| DS-110 / DS-120 | 未打开终端 / 终端初始化超时 |
| DS-201 | SSH 持续 90 秒未收到任何数据（包括心跳与终端数据） |
| DS-202 | SSH 底层传输结束或网络错误 |
| DS-210 | 远端 Shell 或终端通道结束，需结合传输日志判断原因 |
| DS-211 / DS-212 | 终端输入失败 / 创建或启动远端终端失败 |
| DS-220 / DS-221 | 本地终端通信通道关闭 / 向窗口发送数据失败或超时 |
| DS-230 / DS-231 | 旧版后台命令清理超时；本次修复已移除该类主连接强制断开 |
| DS-240 | 旧版 SFTP 清理超时；本次仅关闭文件通道，保留 SSH 终端 |
| DS-290 | 前端无法取得后端诊断记录；需反馈截图及现有日志 |
| DS-299 | 关闭时暂未捕获更具体的触发原因 |

日志每 5 秒记录一次本地心跳状态，并记录连接、断开和传输结束事件。只包含时间、随机连接编号、固定错误分类及延迟数据；不记录命令或终端内容、服务器地址、账号、密钥和口令。日志不自动上传。

诊断码标识程序首先观察到的触发条件。例如 DS-201 能证明心跳超时，但仅凭该码无法确定是运营商链路、代理还是服务器本身引起。应结合断开前的心跳等待时间、传输结束事件及实际网络环境分析。

本次同时包含重连保留历史显示、重连失败后再次尝试，以及短时网络抖动恢复的修复。旧终端记录只用于显示，不会重新发送或执行；新会话不会继承旧终端的全屏程序或鼠标输入模式。
