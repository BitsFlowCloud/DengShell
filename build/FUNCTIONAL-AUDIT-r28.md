# DengShell R28 功能验证

日期：2026-09-14；构建号 `20260914028`。

## 本次变化

Arch pacman 版新增启动检查、用户确认下载、发行签名和包身份校验、系统安装授权及安装后重启。发行版身份独立于是否额外安装 dpkg，DEB 和 Arch 不会混用更新包。Windows/DEB 继续使用已有更新端点。Arch 包新增 polkit、libarchive、pacman 依赖；旧 Arch 客户端需先手动安装本版。

## 已完成的源码与界面验证

- `go test ./...` 全部通过；更新相关测试通过 race 检查。
- 覆盖 Arch/Manjaro/CachyOS、Debian/Ubuntu、RPM 系列的安装类型选择，拒绝混淆的发行版身份。
- 验证 Arch 发行签名绑定包类型；拒绝 DEB 混用、平台字段篡改、错误包名/架构/版本、重复身份字段及超大元数据。
- 安装命令使用独立参数；包含中文、空格和 Shell 符号的文件路径不执行为命令。普通用户缺少授权工具时拒绝绕过授权。
- 实际 Chromium 加载应用全部 CSS 与更新脚本，验证浅/深色 Arch 提示、确认安装、设置保存、失败重试、下载创建期间取消及不支持发行版的手动下载入口。原生桥使用隔离替身。
- R28 原生 Linux 二进制在 Ubuntu 22.04/24.04、Debian 12、Fedora 43、openSUSE Tumbleweed、Arch 容器中启动原生 GTK3/WebKitGTK 界面，全部运行库解析成功。

Arch 隔离容器中实际运行 R28 更新助手，调用 pacman 将安装升级为 QA 专用下一构建包，重启原生界面并核对收据、原配置密钥与字体/背景测试文件；数据库锁冲突时保留锁和旧包，重新打开旧程序。R20、R27 原始更新助手也已实际安装 R28 DEB 并重启。

最终发行附件 `RELEASE-VALIDATION-r28.json` 单独记录安装包完整性、真实包安装/卸载与更新助手测试结果。它不把此前版本的其他功能验证冒充本轮全量人工测试。

## 边界

真实 Linux 更新事务以隔离容器 root 身份运行，原生界面使用 Xvfb/软件渲染；不代替实体桌面的 polkit 授权代理、Wayland、显卡和托盘验证。模拟下一版 Arch 包只用于隔离升级测试，不上传、不用发行私钥签发。Windows 本轮交叉编译与压缩/安装包静态检查，不宣称实机升级或安装/卸载通过。

未使用或改动实际用户配置、SSH 密钥、自定义字体与背景。官网由用户自行部署；本地与 GitHub 文件完成不代表官网已上线。
